# /run — ノンストップ自走ループ
CLAUDE.md「自走運用ポリシー」に従い、**この案件（Garage）で「今この瞬間に最も優先すべき1件」を毎回特定**し、actionable が尽きるまで自走で回す。

> 通知: `notify-humanball.mjs` は task 名の頭に自動で **[Garage]** を付与する（複数プロジェクトが同一 LINE チャンネルに来るため、どの案件の人ボールか判別できるように）。--task には素のタスク名を渡せばよい。
>
> **人ボールの提示（画面）と `--detail`（LINE）は、CLAUDE.md「人ボール報告フォーマット（必須）」に従う**：結論先頭・選択肢 A/B/C・推奨1行。LINE(`--detail`) は `決めてほしいこと＋A/B/Cどれ？推奨X` を **1〜2行**に圧縮する。

## 盤面の取得（この案件＝`.env` の BACKLOG_PROJECT_ID で絞る）
- `node scripts/next-target.mjs` … **要件定義済み(Ready)** を優先度順で全件（案件名 relation = BACKLOG_PROJECT_ID で絞り込み済み）。
- 同じ **案件名 relation contains フィルタ**で **進行中 / レビュー待ち / 未整理** も取得する（notion-search は使わない。`data_sources/query` 2025-09-03 で `{status} AND {案件名 relation contains BACKLOG_PROJECT_ID}`）。
- 以降の判定・着手は **この案件で絞った範囲のみ**（他案件のタスクには触れない）。

## 優先順位決定ロジック（毎回これで最優先1件を特定する）
1. **中断中の 進行中 / レビュー待ち** があれば最優先で再開する（既に「進行中」ならそのまま続行）。
2. 次に **要件定義済み(Ready)** を優先順位順（緊急>高>中>低、同率は作成日古い順）で1件。**着手時にまず Notion を「進行中」に更新**してから進める。
3. Ready が空 → **未整理(Inbox)** を優先順位順で **1件ずつ** 見て内容を判定する：
   - **(a) 意図・業務判断が必要**（仕様が曖昧で人にしか決められない）／**本文が空・不足で要件化の材料が無い**
     → 人ボール「要回答」として記録し **実装はしない**。LINE 通知（フォーマット必須・1〜2行に圧縮）：
       `node scripts/notify-humanball.mjs --kind 要回答 --task "<タスク名>" --detail "<決めてほしいこと1行／A.… B.…／推奨X>" [--url "<セッションurl>"]`
     → そのまま **次の未整理へ進む（止まらない）**。
   - **(b) 情報十分で要件化できる**（本文からストーリー＋AC＋スコープを起こせる）
     → CC が要件化（薄いストーリー＋受け入れ条件(AC)＋スコープ）し、ステータスを **要件定義済み** に更新 → **実装に入る時に「進行中」へ更新** → そのまま実装まで自走する。
     → 要件化の途中で「実は意図/業務判断が要る」と判明したら、その場で **(a) に格下げ**して人ボール化（勝手に決め打ちしない）。
   - 未整理を1件処理したら **必ず 1 に戻る**（Ready が生まれる／(a) で park する／未整理が尽きる まで繰り返す）。
4. **Ready も 未整理も無い**（中断中も無い）→ **本当に手が無い**ので停止して報告。停止直前に LINE 通知：
   `node scripts/notify-humanball.mjs --kind 要回答 --task "Inbox棚卸し：手詰まり（actionable なし）" --detail "<決めてほしいこと1行／A.… B.…／推奨X>" [--url "<セッションurl>"]`

**【重要】「未着手（未整理）だから検知できず止まる」状態をなくす。** /run は常に上記で最優先1件を特定し、**Ready が無くても未整理から拾って前進**させる（要件化 or 人ボール化）。**停止するのは本当に手が無い時だけ**。

## 1件の進め方（特定した最優先タスク）
- **着手したらまず Notion ステータスを「進行中」に更新**（`notion-update-page` 相当 or 既存スクリプト）してから設計・実装に入る。これで Notion 上で「今 AI が実装中のタスク」が一目で分かる。
  - Ready から着手 → まず「進行中」に更新してから着手。
  - 未整理を (b) で要件化した直後も、実装に入る時に「進行中」に更新。
  - 中断中の「進行中」タスクの再開は既に「進行中」なのでそのまま。
  - 原則 **同時に「進行中」になるのは1件**（1タスクずつ自走するため）。
- 遷移は **要件定義済み →(着手)→ 進行中 →(実装完了)→ 本番待ち**。
- 設計 → 実装 → **ローカル検証を全 green**（`pnpm test`／必要に応じ `scripts/verify-*.mjs`）→ **dev にマージ** → Notion を「本番待ち」に更新。レビュー待ちは経由せず自己チェックで本番待ちへ。
- 検証が 3 回直しても緑にならない → 人ボール「要対応」に記録してスキップ。記録後に LINE 通知（フォーマット必須・1〜2行）：
  `node scripts/notify-humanball.mjs --kind 要対応 --task "<タスク名>" --detail "<失敗の要点1行／A.直す B.スキップ確定／推奨X>" [--url "<セッションurl>"]`
- 1ユニットごとに非ブロックの1行サマリを出し、**優先順位決定ロジックの 1 へ戻る**。

## 停止条件（ここで初めて止まりサマリ報告）
- **Ready も、未整理の (b) も無い**（＝中断中も無く、未整理は全部 (a) で park 済み or そもそも空）→ 停止して報告（人の確定待ち）。※「Ready 空 → 必ず停止」は禁止。**(b) があれば必ず着手して継続**する。
- 本番待ちがあり他に actionable 無し → 「本番待ち N 件。/ship で承認を」。
- 安全弁：1回の run で最大 8 ユニット or 30 分で打ち切り、続きは再 /run。

## 厳守
- 本番デプロイ / main マージ / db push は絶対にしない（/ship 専用）。migration は作成のみ。
- 人ボール化したタスクは人の回答が入るまで再着手しない（同じ問いでループしない）。
- 判定・着手は **この案件（BACKLOG_PROJECT_ID）で絞った範囲のみ**。他案件のタスクには触れない。
- いつでも中断可能。
